# 合成样本构造规范（SYNTHETIC.md）

> 2026-09-23 建立 ｜ 语料库 v0.3 ｜ 与真实票样分目录（`tests/corpus/synthetic/`）
> 目的：在合法、可追溯的前提下补齐 DeepSeek 评审钉死的覆盖项（红冲/差额/多税率/中文·拼音方言），
> 并明确合成样本与"凭空编造（plausible fiction）"的本质区别。

## 一、合法性边界（为什么现在可以合成）

v0.1 调研结论"AI 合成样例禁用"针对的是**无 schema 依据、凭空编造票面**（越南 dev.to 复盘：合成 6 份 5 份是 fiction，真实票一来暴露 3 个 bug）。

本轮调研打通了合法合成路径，三重前提缺一不可：

1. **官方 schema 依据**：财政部《电子凭证会计数据标准——全面数字化的电子发票（推广应用版）》公开（XSD/taxonomy + 元素清单 + 官方实例文档），字段语义有权威出处；
2. **业务规则依据**：差额/红冲要素字段来自 GB/T《电子发票业务数据规范 第2部分：特定要素》与总局公告 2024 年第 11 号；服务商公开文档（金蝶红票算法/差额注意事项）交叉印证；
3. **显式标注**：manifest 标 `synthetic=true` + `source_tier=synthetic_schema_based` + `construction_basis`，与真实票样物理分目录，任何消费者可区分。

合成样本用于**结构级健壮性测试**（parser 能否正确解析这类结构、勾稽是否成立），**不用于**：
- 冒充真实票样进入来源统计（每省≥2 份真实票门槛合成样本不计入）；
- 验证规则的业务真实性（差额/红冲的真实票面字段布局仍需真实票核验）。

## 二、字段依据来源（权威出处表）

## 三、构造硬规则（所有合成样本必须满足）

1. **勾稽自洽**：`金额 + 税额 = 价税合计`（容差 ±0.01）；多税率样本 Σ明细=合计；
2. **票号 20 位数字**：1-2 年度后两位 / 3-4 省级税务局区域代码 / 5 渠道 / 6-20 顺序（总局 2024 年第 11 号第四条）；合成票号必须唯一且不与真实票样冲突；
3. **主体全虚构**：销售方/购买方名称、税号、地址、电话全部虚构（沿用语料库脱敏纪律），税号保留 18 位结构；
4. **结构同构优先**：EInvoice 结构样本基于真实票样（gaode-js-taxi.xml）同构扩展；中文/拼音方言样本键名必须落在 parser `_ALIAS` 或 GB/T 字段字典内；
5. **文件头注释**：每个合成样本 XML 头部注明"synthetic"、字段依据、构造口径、校验状态；
6. **manifest 强制标注**：`synthetic=true`、`source_tier=synthetic_schema_based`、`construction_basis`（缺一不可，测试断言）。

## 四、校验状态与边界（诚实声明）

- 财政部官方验证工具（`电子凭证会计数据标准文件验证工具.zip`）仅支持 Windows 10 64 位，当前 Linux 开发环境未运行；合成样本的**结构级校验**=与语料库真实票样同构比对 + 测试勾稽断言（`test_corpus.py`）；
- 官方 XSD（`einv_entry_point_2023-12-31.xsd`）针对的是 XBRL 实例文档 taxonomy，**不适用于票面 XML**；官方 XBRL 实例样本保持官方原貌（脱敏主体后入库），无需额外校验；
- **未核验项（登记 v1 硬门）**：真实红冲 EInvoice 的字段布局（当前红冲样本为中文方言构造）、真实差额票面（KCE 在真实 EInvoice 中的位置）、真实多税率票。拿到真实票后必须回填核验并修订合成样本。
